# Design: add-duan-first-bi-break-rule

## 1. 原文依据（GitHub 108 课全文，`stockServ/chzhshch-108-plus`）

**65 课《再说说分型、笔、线段》**（`0593-*.md`）：
> 「线段至少有三笔……线段有一个最基本的前提，就是线段的前三笔，必须有重叠的部分。」
> 「对于从向上一笔开始的，其中的分型构成这样的序列：`d1g1d2g2d3g3…dngn`。如果找到 i 和 j，`j>=i+2`，
> 使得 `dj<=gi`，那么称向上线段被笔破坏。」（向下对称）

**67 课《线段的划分标准》**（`0614-*.md`）：
> 特征序列两相邻元素间没有重合区间 = 缺口；分型三种情况（现实现已有）；
> 第二种情况：「如果从该分型最高点开始的向下一笔开始的序列的特征序列出现底分型……该线段在该顶分型的高点处结束」。

**71 课《线段划分标准的再分辨》**（`0639-*.md`）——本次修复的核心依据：
> 「就是**最早破坏那笔就是转折点下来的第一笔**，这种情况下，这一笔……属于中间地带，既不能说是前面一段的
> 特征序列，更不能说是后一段的特征序列……一旦该笔延伸出三笔以上，那么新的线段就形成了。」
> 「从转折点开始，如果**第一笔就破坏了前线段，进而该笔延伸出三笔来，其中第三笔破点第一笔的结束位置**，
> 那么，**新的线段一定形成，前线段一定结束**。」
> 复杂分支：「第三笔完全在第一笔的范围内……1、最终还是先破了第一笔的结束位置，这时候，新的线段显然成立，
> 旧线段还是被破坏了；2、最终，先破第一笔的开始位置，这样，旧线段只被一笔破坏，接着就延续原来的方向，
> 那么，显然旧线段依然延续，新线段没有出现。」

**对照结论**：`findSegmentEnd` 的 `first === null`（候选转折笔 = 段内第一根反向笔，转折点前无特征序列元素）
正是 71 课「最早破坏那笔就是转折点下来的第一笔」情形——特征序列分型（67 课）结构上无从成立，必须用
第一笔破坏规则补充。当前实现缺失该规则，与 67/71/65 课组合语义不符。

## 2. 算法设计（`findSegmentEnd` `first === null` 分支）

判据为方向对称的纯函数 `firstBiBreak(bis, prevTurnBi, segmentDirection) -> 'confirmed' | 'extended' | 'none'`：

```
转笔 = prev（段内第一根反向笔，从假设转折点 T 开始）
turnEnd   = Up 段 ? 转笔.low : 转笔.high      // 转笔终点（「第一笔的结束位置」）
turnStart = Up 段 ? 转笔.high : 转笔.low      // 转笔起点（= 假设分界点 T 的极值）

for i in 转笔.biIndex+1 .. bis.length-1:      // 按时间顺序竞争，先到者定论（71 课复杂分支：无限扫描）
  if 段向 Up（转笔为 Dn）:
    与转笔同向(Dn) 且 low < turnEnd   → return 'confirmed'   // 第三笔起破转笔终点 → 前段结束
    与段同向(Up)  且 high > turnStart → return 'extended'    // 先破第一笔起点（T）→ 旧段延续，判据作废
  段向 Dn 对称（Up 笔破 high > turnEnd → confirmed；Dn 笔 low < turnStart → extended）
return 'none'                                              // 无突破 → 判据不确认，走常规流程
```

调用点（`findSegmentEnd`）：

```ts
if (first !== null) { ...现有 67 课分型 + case1/case2 流程... }
else {
  // 71 课第一笔破坏判据（此前是「跳过判定 + 转折笔并入 stdSeq」——本 bug 根源）
  const braking = this.firstBiBreak(bis, prev, direction);
  if (braking === 'confirmed') {
    return { endIdx: prev.biIndex - 1, nextStart: prev.biIndex }; // 段在 T 结束
  }
}
stdSeq = this.mergeFeatureInclusion(stdSeq, prev, direction);     // extended/none → 常规吞并继续
```

**先到者竞争的两条细节**（预演修正过程实证）：
1. 扫描必须从**转笔的下一笔**开始（第 2 笔也可能先破转笔起点 → 立即作废），而不是从触发点之后——
   否则第 2 笔被漏检，误把「反弹破前顶」当破位（预演中段#0 曾因此被误伤，修正后与原输出一致）；
2. **只有与转笔同向的笔**才能判「破转笔终点」（转笔 Dn 时是 Dn 笔跌破转笔低点）；段向笔的低点
   回落不构成破位（预演中 bi#62 场景实证）。

**单笔段恒成立**：转笔是段内第一根反向笔 → `prev.biIndex === segStartIdx + 1`（笔方向交替）→
确认时 `endIdx === prev.biIndex - 1 === segStartIdx` → 判据确认的段恒为单笔。

## 3. 单笔段输出决策（keep，用户已确认）

- **keep（采纳）**：`type=complete, status=valid`，`startBi === endBi === 该笔`。依据：71 课「前线段
  一定结束」承认被一笔破坏的前段；段方向严格交替得以保持（10:40 顶成为 `Up[38..38]` 的终点与
  `Dn[39..45]` 的起点）；下游（段中枢/买卖点/前端）无孤儿笔与同向相邻段风险。65 课「至少三笔」的
  通用约束不适用于该显式特例（71 课补充规则优先）。
- **drop（弃用）**：不输出单笔段、起点推进到转笔 → 锚点 A 处 bi#38 成为孤儿笔，出现
  `Up[88..92] → 孤笔93 → Up[94..98]` 同向相邻段（预演实证 3 处），破坏线段方向交替的基本结构与
  「线段破坏的充要条件是被另一线段破坏」（65 课）语义。

## 5. 弃用方案记录（不实施）

- **case2Confirmed 口径收敛**（原 issue 文档 §6 方向）：已被复现日志证伪——两锚点从未进入
  `hasGap/case2` 分支（最终均为 `gap=false` case1），按此修复锚点不会自愈。
- **段起点有效结构校验推广**（对 `nextStart` 复用 `findValidSegmentStart`）：非 65/67/71 课文规则
  （`check_init_seg` 只是实现细节），连锁影响面更大，且无法区分「真转折」与「段起点即极值」。
- **drop（单笔段不输出）**：见 §3，破坏方向交替，弃用。
